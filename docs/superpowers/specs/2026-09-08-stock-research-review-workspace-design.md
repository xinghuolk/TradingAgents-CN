# 个股研究与复盘工作区设计

> 状态：已确认，可用于编写实施计划。
>
> 日期：2026-09-08

## 1. 目标

TradingAgents-CN 作为唯一产品入口，新增面向个人投资者的长期研究与复盘工作区，将现有股票行情、AI 分析报告、真实持仓、真实成交和模拟交易串联起来。

本功能解决三个问题：

1. 为每只股票维护持续更新的投资论点和研究材料。
2. 用低负担的 Markdown 笔记记录日常观察，并在需要时形成正式调研或决策快照。
3. 按需创建例行复盘或决策复盘，保留 AI 草稿、人工结论及其依据。

目标工作流为：

```text
筛选 / 自选
  -> AI 分析与人工调研
  -> 当前论点、笔记和研究材料
  -> 可选的人工决策快照
  -> 模拟执行或真实成交导入
  -> 按需复盘
```

## 2. 设计原则

- 面向个人使用，减少必填项和流程门禁。
- AI 输出是分析建议或草稿，不是用户的正式决策或复盘。
- 真实券商事实、模拟交易事实和研究解释分别管理，通过稳定引用关联。
- 真实账户与模拟账户始终分开显示，不混算持仓或收益。
- 研究内容以 Markdown 为主，仅结构化保存检索、关联和复盘真正需要的字段。
- 缺少非关键资料时允许继续编辑和确认，以明确提示代替阻断。
- 复用现有 FastAPI、MongoDB、模型配置和分析任务基础设施，不移植 `../stock` 的 SQLite、Markdown 文件存储或独立定时器。

## 3. 范围

### 3.1 包含

- 全局研究中心 `/research`。
- 个股研究工作区 `/research/:code`。
- 当前投资论点及其版本历史。
- Markdown 笔记和调研文档。
- 人工决策快照。
- 按需创建的例行复盘和决策复盘。
- AI 笔记、调研和复盘草稿。
- 对现有分析报告、真实成交、模拟成交、决策及持仓日期的引用。
- 草稿自动保存、人工版本保存、归档、回收站、恢复和永久删除。

### 3.2 不包含

- 自动创建每日复盘。
- 复盘提醒、待办、逾期状态或完成率。
- 自动下单或真实券商交易连接。
- 真实账户与模拟账户的合并统计。
- AI 模型排名、建议命中率、收益归因或人工修改幅度统计。
- PDF、图片和其他附件上传。
- `../stock` 历史笔记、决策或复盘数据迁移。
- 通用迁移工具或通用知识库平台。
- 每日行情自动更新。该能力后续使用独立 spec 设计。

## 4. 页面与导航

### 4.1 现有个股详情

`/stocks/:code` 保持行情详情职责，包括行情、K 线、新闻、公告、基础资料和现有 AI 分析摘要。页面新增“研究工作区”入口及最近研究更新时间，不嵌入完整编辑器。

### 4.2 全局研究中心

`/research` 使用目录型首页，而不是仪表盘或完整时间线。每只股票显示：

- 股票名称、市场和代码。
- 当前论点摘要。
- 最近更新时间。
- 最近记录的类型和时间。
- 真实持仓或模拟持仓标识，两者分别展示。

页面支持按股票代码或名称搜索，并按市场、真实持仓、模拟持仓和自选状态筛选。主要操作为创建或进入个股工作区，以及新建例行复盘。

### 4.3 个股研究工作区

`/research/:code` 采用文档优先布局：

- 顶部显示股票名称、标准证券标识、保存状态、返回行情入口和主要操作。
- 左侧为当前论点、笔记、调研、决策和复盘导航。
- 右侧为列表或 Markdown 编辑区。
- 窄屏下左侧导航折叠为顶部页签或菜单，编辑区保持单列。

默认进入“当前论点”。笔记、调研、决策和复盘均在各自导航项内显示列表，再进入选中记录的编辑或只读视图。

## 5. 内容模型与行为

### 5.1 当前论点

每位用户、每只标准证券只有一个当前论点，包含：

- Markdown 正文。
- 关键假设。
- 主要风险。
- 失效条件。
- 待确认问题。
- 标签和外部链接。

编辑内容自动保存当前草稿。自动保存不生成历史版本。用户点击“保存版本”时生成可命名快照；确认决策或正式复盘时也自动生成当时的论点快照。

复盘结论不自动改写当前论点。正式复盘保存后可以选择“应用到当前论点”，先显示差异，经用户确认后更新当前论点并生成新版本。

### 5.2 笔记

笔记用于快速记录，最少只需要标题和 Markdown 正文。标签、外部链接和站内引用均为可选。

笔记以自动保存的可编辑文档存在。用户可以将笔记转换为调研记录；转换只改变记录类型和补充字段，不复制内容。

### 5.3 调研

调研和笔记共用 Markdown 编辑器，并增加：

- 调研主题。
- 资料引用。
- 当前结论。

调研模板不设必填完整度。用户可以在笔记和调研之间转换记录类型，转换不复制正文。

### 5.4 决策快照

决策动作包括买入、加仓、减仓、卖出和继续观察。最小字段为：

- 动作。
- 决策日期。
- Markdown 正文。
- 可选的计划价格、目标仓位、计划期限和引用资料。
- 创建时的当前论点、关键假设、风险及失效条件快照。

除动作和日期外均不强制填写。AI 的交易建议可以作为草稿来源，但必须由用户确认后才成为决策。

正式决策不允许被后续自动保存覆盖。判断变化时创建新决策。决策不要求关联成交；用户可以后补、修改或取消关联。

### 5.5 复盘

复盘仅在用户主动操作时创建，不由系统按日期或事件自动生成。创建时选择：

- 例行复盘：不要求关联历史决策。
- 决策复盘：可以选择一个历史决策，并引用相关成交、持仓和后续研究。

从全局研究中心创建例行复盘时，默认范围为市场和当前真实持仓；从个股工作区创建时，默认范围为当前股票。用户可以在创建时调整范围。

精简复盘模板包含：

- 市场与持仓表现摘要。
- 重要事实、公告和调研变化。
- 当前论点是否发生变化。
- 后续观察事项。

资金流、全球市场、涨停概念和完整财务指标作为可选资料，不要求每次采集或填写。

复盘先作为可编辑草稿保存。用户确认后成为正式复盘并生成版本快照。正式复盘可以继续修订，但每次修订产生新版本。

### 5.6 保存与删除

- 编辑内容每隔数秒自动保存到 MongoDB。
- 自动保存只更新当前草稿，不生成历史版本。
- 用户点击“保存版本”时可以填写简短版本说明。
- 删除先进入回收站；回收站记录可以恢复或由用户手动永久删除。
- 系统不设置自动清理期限。
- 历史版本只能查看，或恢复为一个新版本，不能直接修改。
- 删除或归档研究记录不级联删除分析报告、成交或持仓事实。

## 6. 数据模型

数据存入应用现有 MongoDB。服务层负责文档编码、版本写入和用户作用域，Router 和前端不直接拼装数据库查询。

### 6.1 `stock_research_workspaces`

每位用户、每只证券一条当前工作区记录。主要字段包括用户 ID、标准证券标识、市场、代码、名称、当前论点、关键假设、风险、失效条件、待确认问题、标签、外部链接、当前版本和时间戳。

标准证券标识使用 `market:code` 格式。`user_id + security_id` 建立唯一索引，`updated_at` 用于全局研究中心排序。

### 6.2 `stock_research_entries`

统一保存笔记、调研、决策和复盘。通用字段包括：

- 条目 ID、用户 ID 和记录类型。
- `stock` 或 `portfolio` 范围。
- 主证券标识及关联证券标识数组。
- 标题、Markdown 正文、状态、标签和外部链接。
- 结构化引用。
- 各记录类型的专用字段。
- AI 原始草稿和来源元数据。
- 当前版本、确认时间、归档时间和删除时间。

股票笔记、调研和决策只有一个主证券标识。全局例行复盘可以关联多只股票；同一复盘通过证券标识数组显示到对应个股工作区，不复制正文。

索引覆盖用户与条目 ID、用户与证券标识、用户与记录类型，以及回收站查询。

### 6.3 `stock_research_revisions`

版本记录保存目标类型、目标 ID、递增版本号、完整内容快照、保存原因和时间。`user_id + target_type + target_id + revision` 建立唯一索引。

自动保存不产生版本。用户主动保存版本、确认决策、确认复盘、将复盘结论应用到当前论点，以及从旧版本恢复时产生新版本。

### 6.4 引用

引用保存来源种类、稳定 ID、账户类型、日期和必要的展示标签。支持分析报告、真实成交、模拟成交、决策和持仓日期。

引用不拥有来源数据。来源不可用时保留引用并显示提示，不级联删除研究内容。

### 6.5 `stock_research_generation_tasks`

AI 草稿任务使用独立集合，保存任务 ID、用户 ID、目标条目、冻结后的上下文引用、模型配置、任务状态、错误信息和时间戳。它复用现有 worker 运行方式，但不进入股票分析报告列表。

任务只保存生成所需的引用与必要输入快照，不重复保存完整的持仓或成交事实。

## 7. AI 草稿

AI 草稿复用系统已有模型配置。生成对话框允许选择已配置模型、思考级别和本次引用资料，并默认使用用户最近一次选择。不新增研究专用模型配置。

所有 AI 产物统一记录服务商、模型名称、思考级别、生成时间、来源报告或任务 ID、提示模板版本和完整引用列表。思考级别是模型调用配置，不保存模型内部思维过程。旧分析报告缺少字段时显示为空，不推断或补造数据。

生成前，系统预选相关资料。用户可以调整引用，并选择模型和思考级别。生成任务复用现有后台任务基础设施。

生成成功后，系统保存不可覆盖的 AI 原始草稿和来源信息。用户在独立的人工正文中编辑并确认。

例行复盘默认选择指定日期或区间的行情、市场摘要、真实持仓、成交、当前论点和近期记录。决策复盘默认选择历史决策、关联成交、决策前后持仓、期间行情、后续记录和分析报告。

AI 调用不静默切换模型。所选模型不可用时任务失败，用户可以重新选择。失败不创建空白草稿，也不修改人工内容。

## 8. 决策与成交关联

成交事实继续由真实持仓模块或模拟交易模块管理，研究模块只保存关联关系。系统按证券和时间推荐候选记录，用户负责确认、修改或取消关联。

一项决策可以关联多笔分批成交，一笔成交最多关联一项决策。真实与模拟成交分别标记，不能混淆账户类型。

决策不是交易门禁。没有决策的成交仍可导入、查看和用于例行复盘。

## 9. 后端边界

新增独立研究模块：

- Router 统一挂载在 `/api/research`。
- 服务代码位于 `app/services/stock_research/`。
- Repository 负责四个研究集合及其索引。
- 研究服务编排工作区、条目、版本和引用。
- AI 草稿服务负责构造上下文并提交后台任务。

研究模块通过现有服务接口读取分析报告、真实持仓和交易数据，不直接修改其集合。证券标识与真实持仓使用相同的 `market:code` 表达，但本项目不为此重构现有持仓模块。

公开 API 按以下资源组织：

- `/api/research/workspaces`：研究目录、创建工作区和个股工作区读写。
- `/api/research/entries`：条目列表、创建、更新、确认、类型转换和归档。
- `/api/research/revisions`：版本列表、详情和恢复。
- `/api/research/trash`：回收站列表、恢复和永久删除。
- `/api/research/references`：按证券和类型查询可引用资料。
- `/api/research/links`：查询推荐关联，以及确认、修改或取消决策成交关联。
- `/api/research/generation-tasks`：提交 AI 草稿任务并查询状态和结果。

具体请求字段在实施计划中映射到上述资源，不新增第二套 API 前缀。所有接口保持用户作用域和统一错误响应。

## 10. 错误处理

- 无效证券标识和无效记录类型阻止保存。笔记缺少标题或正文时阻止保存；决策只校验动作和日期。其他非关键字段按对应记录类型允许留空。
- 缺少非关键引用时允许保存，并返回可展示的警告。
- 自动保存失败时前端保留未提交内容，显示保存失败状态并允许重试。
- AI 任务失败只更新任务状态，不创建空白草稿或覆盖人工内容。
- 来源记录不可用时保留引用快照并显示来源不可用。
- 归档、恢复和版本恢复不级联修改分析报告、持仓或成交事实。
- 所有读取和写入均按当前用户隔离。

本功能面向个人使用，不增加多人实时协作。普通编辑采用最后一次成功保存的内容，并依靠版本历史恢复关键状态。

## 11. 交付顺序

功能分四个可独立验收的阶段：

1. 研究基础：MongoDB 集合、索引、API、研究目录、个股工作区、当前论点、笔记、调研和版本历史。
2. 决策与引用：决策快照，以及分析报告、真实成交、模拟成交和持仓日期的引用。
3. 人工复盘：按需创建例行复盘或决策复盘，支持全局或个股范围、确认、归档和恢复。
4. AI 草稿：可调整上下文、模型和思考级别，异步生成草稿并记录来源。

每日行情自动更新不属于这四个阶段，后续单独设计和实施。

## 12. 测试策略

- 服务层使用内存 MongoDB 替身测试保存、版本、归档、引用和用户隔离。
- Router 测试覆盖认证、输入边界、用户作用域和响应格式。
- AI 服务使用假模型测试上下文选择、来源记录、模型不切换和失败处理，不调用真实 LLM。
- 真实 MongoDB、Redis、行情数据源和 LLM 检查保持 opt-in。
- 前端不为本功能新增测试框架；使用生产构建检查，并通过 Playwright 验证关键用户流程。
- 新增的服务级测试纳入仓库快速验证范围。
- 实施时按实际架构变化更新 `ARCHITECTURE.md`，按测试入口变化更新 `docs/testing.md`。

## 13. 验收标准

- 用户能从研究目录创建或打开任意股票的研究工作区。
- 当前论点、笔记和调研可自动保存，并能手动保存和恢复版本。
- 用户能创建轻量决策，确认后保留当时的论点快照。
- 用户能从全局或个股入口按需创建例行复盘，也能创建可选关联决策的决策复盘。
- 全局复盘只保存一份，并能在所有关联股票的工作区中找到。
- 用户能将分析报告、真实成交、模拟成交和持仓日期作为引用，来源缺失不会破坏研究内容。
- 决策与成交关联由系统推荐、人工确认，不影响原有导入和交易流程。
- AI 草稿生成前可以调整资料、模型和思考级别；生成后保留原始草稿、来源元数据和人工版本。
- 不存在自动复盘、复盘提醒、严格审批或 AI 模型效果评估。
- 真实账户和模拟账户在所有引用、页面和复盘上下文中保持分离。
